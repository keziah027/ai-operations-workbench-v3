# AI运营分析台

当前版本为 **V3**。在 V2.2 的基础上增加可选的“⑥ AI运营助手”。原有五模块、Excel/公开账号/自有后台入口、人工标注、存档、图表和下载继续保留。V3 文件与验证说明见 [V3 更新说明](CHANGELOG_V3.md)，历史功能说明见 [V2.2 更新说明](CHANGELOG_V2.2.md)。

使用 Python、Streamlit、pandas。只有新增 AI 功能需要 API Key；没有密钥时，原有本地分析照常运行。此次只新增一个直接依赖：官方 `openai` SDK。

## V3：先体验本地功能，再按需配置AI

升级后先运行一次 `install.cmd` 安装新增依赖，再双击 `start.cmd`。这是源码项目，其他电脑仍需安装 Python 和依赖，不是免安装程序。

1. 在 OpenAI API 平台自己的项目中创建 API Key。不要把密钥发给聊天或写进 Excel。参见[官方入门说明](https://developers.openai.com/api/docs/quickstart)。API 的权限、额度和计费以你的 API 项目为准。
2. 打开项目的 `.streamlit` 文件夹，把 `secrets.toml.example` 复制一份，命名为 `secrets.toml`。Windows 请显示文件扩展名，避免变成 `secrets.toml.txt`。
3. 用记事本打开 `secrets.toml`，把 `your-api-key` 换成自己的密钥，保存。示例模型是 `gpt-4.1-mini`，需要你的项目有对应权限；可换成支持 Responses 和结构化输出的模型。不承诺当前账号可用的模型或价格。
4. 重新启动工作台，上传或读取账号笔记，打开“⑥ AI运营助手”。页面检测到配置不等于已验证联网成功。

```toml
OPENAI_API_KEY = "your-api-key"
OPENAI_MODEL = "gpt-4.1-mini"
OPENAI_TIMEOUT = 60
OPENAI_MAX_OUTPUT_TOKENS = 6500
AI_MAX_INPUT_CHARS = 60000
AI_MAX_NOTES = 24
AI_BODY_CHARS = 500
AI_HISTORY_TURNS = 4
```

同名环境变量也可以使用；本项目配置文件中的值优先。真实配置已加入忽略规则，并且不进入交付压缩包。输入上限按字符控制，不是精确 token 或费用估算。

## 生成、修改、采纳和问答

1. 先在原五模块确认身份、领域、目标及主题分类。AI 不会自动改写这些人工内容。
2. 在第六模块查看将发送的摘要：统计范围、文本样本数、正文覆盖、抽样和截断情况。可筛选首发日期、取消发送正文；定位、人群与诊断内部备注默认不发送，需单独勾选。
3. 点击“生成AI分析”。只有这个按钮、“重新生成AI分析”和“发送问题”会请求 API；切换模块、修改字段、下载、上传和重新打开项目不会自动请求。每次点击最多尝试一次，没有后台自动重试。
4. 结果是草稿，分为账号识别与定位、洞察、问题、策略、选题。可在五个文本框中修改；点击“保存草稿修改”保留编辑，点击“保存编辑并采纳”才进入正式报告。“恢复本次AI原稿”恢复编辑框；“撤销/恢复上次采纳”切换最近两次采纳状态。
5. 下方可围绕当前账号发送问题。没有所需日期、分母或程序统计时，应明确显示能力限制，不让模型自己计算新增统计。最多保留当前八轮；发送最近配置轮数的截取文本（每问最多五百字、每答一千四百字）。没有真实用量返回就显示未知，不编造费用。
6. 数据、人工修订、模型或相关配置变化后，旧结果显示过期，不进入当前正式报告。旧对话需要点击“重开当前数据对话”；上一次对话保留供核对，不参与新对话。
7. 点击页面底部的“保存项目”，把草稿、编辑、采纳结论和对话写入本机项目存档。仅刷新浏览器或关闭窗口不等于保存。
8. Excel 和 Markdown 下载包含当前已采纳结果、生成时间、模型、版本、统计事实与笔记证据。勾选“导出时附上未采纳草稿”才能增加独立草稿附录。过期内容不导出到当前报告。问答留在项目存档，不自动成为正式报告结论。

## AI常见问题

| 提示 | 怎么处理 |
|---|---|
| 当前未配置大模型 API，AI 功能暂不可用，本地数据分析仍可正常使用。 | 可继续使用本地五模块；需要AI时再配置本机密钥。 |
| 认证失败 | 核对本机密钥是否有效、有无多余空格；不要发到聊天。 |
| 权限或额度问题 | 在API平台检查项目、模型权限和额度。应用不会自动充值。 |
| 限流 | 等待后主动重试。 |
| 超时或网络错误 | 检查网络后重试；上次有效结果保留。服务可能已处理请求，请以平台用量为准。 |
| 引用、数字、单位或结构校验失败 | 此次响应不会采用，可主动重试或缩小样本。不要把错误响应当结论。 |
| 摘要或对话超出上限 | 缩小日期范围、减少正文长度或重开对话；也可合理调整配置上限。 |
| 只有标题或小样本 | 只能做初步选题和标题判断；AI可以减少建议数量或说明数据不足。 |

本地校验能检查结构、事实编号、笔记编号、摘录和受控数字引用，不能证明所有自然语言解释正确。AI仍是待复核草稿；人工修改与采纳属于用户判断，不会自动通过模型证据校验。累计点赞不能直接解释为每日新增或最近下滑。

接入依据：[官方结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)、[官方SDK说明](https://developers.openai.com/api/docs/libraries)、[示例模型能力](https://developers.openai.com/api/docs/models/gpt-4.1-mini)。使用 Responses API 的严格 JSON Schema，`store=False`，不启用工具、文件访问或模型生成代码执行。请仅发送自己允许交给 API 处理的内容；不宣称该参数等同于零保留承诺。

## Excel 怎么准备

- 文件格式为 `.xlsx`，每行是一篇笔记。可以有多个工作表，表头上方可以放标题或说明。
- 程序扫描每个工作表前 30 行，自动寻找包含标题或完整原始赞藏评字段的明细表。账号总览、透视表不会自动当作笔记读取。
- “读取设置”可以切换工作表或指定表头行；多个明细表存在时，每次分析所选的一个表，不自动合并。
- 至少提供 `标题`（也支持 `笔记标题`），或完整的 `点赞`、`收藏`、`评论` 三列。仅有标题也能进入选题与标题分析；缺少的指标保持为空，不据此生成表现结论。
- 可选列是 `标题`、`发布时间`、`图文/视频`、`内容主题`、`产品系列`。
- 也识别 `内容类型`、`产品系列/内容主题` 和 `内容主题/产品系列` 这些列名。
- 自动识别 `笔记标题` → `标题`、`前台日期` → `发布时间`、`内容形式` → `图文/视频`，以及 `点赞数`、`收藏数`、`评论数` 等常见别名。
- 标题缺失时自动编号；相同标题仍视为不同笔记，不自动去重。
- 点赞、收藏、评论填写非负整数，`1,200` 是精确值；`1.2万`、`2千` 保留原文和近似值，`1千+` 保留下界。三种入口均仅用精确值计算合计、均值、比值和排行。空值及 `—`、`--`、`待补` 等标记保留为未确认，不填成 0。错误文字或负数会提示原始 Excel 行号。
- 发布时间推荐使用 Excel 日期或 `2026-09-01`。`编辑于` 日期不能代替首次发布日期，会保留在明细中并从发布趋势中排除。错误日期同样只影响趋势图。
- 示例文件是虚构数据，包含 12 篇笔记及一条点赞为 0 的笔记。

## 页面显示什么

默认进入“Excel 文件”。“公开账号”可以粘贴主页或分享链接；“我的账号后台”可在专用窗口登录后同步。三个入口有笔记数据时，都会展示 V3 的本地五模块与可选AI助手。

1. 总发布篇数、总点赞、总收藏、总评论，以及三项平均值。
2. 每篇笔记的藏赞比和评赞比，以百分比显示。
3. 点赞、收藏、评论各自的 TOP10；不足 10 篇时显示全部。
4. 按内容主题或产品系列统计内容数量、平均点赞、平均收藏、平均评论；多个字段存在时可以切换。
5. 各笔记点赞排行、各内容类型平均点赞、发布时间与点赞趋势。

计算口径：

- 总发布篇数 = 非空数据行数。完全空白的行会忽略。
- 平均点赞 / 收藏 / 评论 = 对应已确认合计 ÷ 该项已确认篇数。真实的 0 参与计算，未确认值不参与；全部缺失时合计与平均值均显示 `—`。
- 存在缺失或非精确值时，指标卡标注“已确认合计”，并显示三项数据完整度。各 TOP10 只排列该项已确认的笔记。
- 藏赞比 = 收藏 ÷ 点赞；评赞比 = 评论 ÷ 点赞。
- 点赞为 0 或所需互动量缺失时，比例显示 `—`，表示无法计算。这些比例可能大于 100%，不是按曝光量计算的转化率。
- 时间趋势以发布日期分组，计算同一天发布笔记的平均点赞量，不代表每天新增点赞。
- 原有分组表的空值归到“未分类”；动态主题分析会过滤“未分类”“待确认”等占位文字。排名并列时按原表顺序显示。

## 常见情况

- 页面提示缺列：在“读取设置”确认所选的是笔记明细表、表头行正确，并检查列名。

## 直接统计账号：当前能力与限制

公开账号登录使用步骤：

1. 进入“公开账号”，点击“打开小红书登录窗口”。
2. 在打开的小红书窗口点击“登录”，自行扫码或按官方页面提示完成登录。密码和验证码只填在小红书页面。
3. 返回分析台，保持勾选“使用我的小红书登录状态访问目标账号”。
4. 粘贴目标账号主页或分享链接，设置“本次最多读取多少篇”（1～1000，默认 100）。保持勾选“逐篇打开笔记，补充收藏和评论”，点击“开始读取账号数据”。程序会使用刚才登录的同一个浏览器访问目标账号。
5. “关闭小红书窗口”只关闭窗口，保留可能仍有效的登录信息；“清除本机登录”会关闭专用窗口并删除此项目保存的浏览器登录资料。换账号前可以清除后重新登录。

专用浏览器资料保存在项目 `.local/xhs-browser/`，不读取或复制日常 Chrome / Edge 的用户资料。该文件夹已排除在版本管理和提供的项目压缩包之外。浏览器是否已登录以小红书页面为准，工具不会仅凭打开窗口就宣称登录成功。平台登录过期时需要再次登录。

该功能用于本机单人使用；同一个分析台的不同标签页共享这一个专用登录窗口。不要把本项目作为多人共用的远程服务。

- **公开账号**：支持完整主页链接、`xhslink.cn` / `xhslink.com` 分享链接及含链接的分享文字。按设置上限向下滚动加载，按笔记标识去重；连续 3 次滚动没有新笔记时停止，不将此情况视为已读取全部历史。
- 勾选详情读取后，逐篇在同一登录浏览器的新标签页中打开笔记，读取互动栏的点赞、收藏、评论。不会点击点赞或收藏按钮，不采集评论者信息。取消勾选则只读取主页，速度更快。
- 页面显示后台读取进度和“停止读取并保留结果”按钮；停止会等待当前页面操作结束，保留已有数据。登录窗口关闭、网络中断或平台验证也会结束读取。连续 3 篇详情失败后停止；单次最长 30 分钟。结果说明停止原因和详情成功篇数。
- 结果表可点击“打开笔记”手动查看来源。展示三项互动量的已确认合计、平均值、各自 TOP10，以及藏赞比与评赞比。主页账号指标以原文显示。`1千+` 等近似数字不转为精确数，未显示的值不填 0。
- 尚未处理、打不开或被限制的详情会在“数据状态”中标注；对应收藏、评论保持空白，已确认的主页点赞仍保留。中途结果保存在当前运行进程中，关闭分析台不保证保留结果。
- 公开账号不读取浏览、曝光等后台数据，也不把编辑时间当成首次发布时间。需要这些字段时使用 Excel 明细或后续接入自有账号后台。
- 遇到登录、验证或访问限制即停止，由你在小红书窗口中自行处理，再主动点击读取；登录不保证解除平台限制。不处理验证码、不绕过限制、不连续重试。已实测登录后的目标账号可读取，但不能保证所有账号始终可读。

## V2.1：五个通用运营分析模块

三个入口取得笔记后，向下找到“账号运营分析 · V3”。下列是保留自V2的五个本地模块。可提供正文（或“笔记正文”“文案”）、账号简介、账号名称、笔记链接、发布时间、内容形式和后台指标。多个账号放在同一表时，先选择账号；上方基础统计仍针对整个工作表。

1. **账号画像**：身份（品牌、个人创作者、机构等）、领域（MBTI、知识、职场、美妆等，可多选）、运营目标分别记录。身份与领域显示初判证据和置信度，支持人工修改；目标“涨粉、收藏沉淀、销售、咨询、到店”由用户确认，默认不勾选。覆盖全部16种MBTI人格缩写。置信度高/中/低表示本地规则的证据强弱，未经标定，不是预测概率。
2. **内容结构**：展示“这个账号主要在发什么？”。按当前语料的TF-IDF词片段相似性归纳3—7个主要支柱，名称来自文本；样本少或高度重复时可以不足3类，并说明原因。合并读取“内容主题”“产品系列”“产品系列/内容主题”“内容主题/产品系列”等旧列，过滤占位文字。支持修改主题名、补充主题和逐篇调整分类。标题较短、同义表达及隐喻可能归纳不准，需要复核。
3. **高互动规律**：比较有效样本前25%与其余笔记的支柱、封面和表达。涵盖身份标签、痛点、结果导向、情绪、反常识、故事、经历、清单、强观点、人群、场景、提问、数字等，提供原文证据。至少8篇有效笔记且指标有差异才比较。标题、正文和封面仅用已读取/标注记录，两组各至少2篇。页面与导出逐篇列出是否纳入、缩略数字、缺失、零分母或口径不一致等排除原因；结果仅针对这些样本，不代表全账号规律或因果。
4. **内容包装**：展示封面预览、标题特征、正文结构和开头结尾。只有标题时仅分析初步选题和标题，缺正文不等于没有相关表达。封面类型需人工标注，不调用视觉模型。
5. **运营诊断**：综合身份、领域与目标选择分析重点。个人创作者关注人设、专业与信任线索；知识/MBTI关注知识表达；美妆关注使用与测评；生活方式关注场景与情绪。销售目标或已读取的商品入口、购买等实际文字线索启用商品承接分析，不再由“品牌电商”单选控制，也不把线索当成目标确认或成交证明。收藏、咨询、到店、涨粉目标分别增加相应诊断。正文诊断至少需要3篇正文及2篇线索，不足时显示“当前数据不足，暂无法判断”。

每个支柱保留篇数、占比、平均点赞/收藏/评论、藏赞比/评赞比及有效篇数。**藏赞比 = 收藏÷点赞，评赞比 = 评论÷点赞；支柱结果是逐篇比值的平均值**。点赞为0、缺失或非精确值不参与。这些比值可能超过100%，不是曝光转化率。

有后台数据时，增加曝光、观看、涨粉表现，以及按支柱、内容形式和首发日期的比较。**观看曝光比 = 观看÷曝光；每千次观看涨粉 = 涨粉÷观看×1000**。仅使用同一篇的精确数字和正分母。可在表中补充“观看统计周期”“曝光统计周期”“涨粉统计周期”及相应“统计口径”列；两侧不一致或只提供一侧时不计算。未提供这些列时按同一来源行计算，需要用户核对来源口径，不混用账号期间总览与笔记明细。按首发日期比较的是笔记当前表现，不是每日新增数据。

三种入口统一保留每个数字的原文、数值和精度（精确、近似、下界、缺失、无效）。例如 `1.2万` 的估计数值是12000，但精确“点赞”列为空，不参加精确统计。可在页面展开数字精度或从导出明细查看。

这五个模块仍是本地文本分析，无API费用。主题归纳不等同于大模型语义理解，兴趣人群假设不代表真实粉丝画像。人工修改优先；改变身份或目标不会重新套用固定主题，也会保留逐篇标注。新读取结果按项目匹配规则恢复人工状态，不确定的记录需要人工核对。
